Cultivator Idle: Command Reference

Every npm command for running, testing, simulating, and shipping the game. Run all of them from the repo root.

First-time setup

npm install

Installs Electron, Capacitor and everything else. If NODE_ENV=production is set on your machine, npm skips dev dependencies. Use npm install --include=dev instead.

You need Node 22 or newer. The smoke tests use Node's built-in WebSocket and fetch.

Run the game dev

npm start

Launches the Electron app from source. Because it runs unpackaged, the character-select screen shows purple dev preset slots: late-game test characters you can jump straight into (see docs/systems/dev-presets.md).

npm run dev

Same as npm start, plus --inspect so you can attach a Node debugger to the main process.

Save files live in %APPDATA%\Cultivator Idle\ on Windows.

Tests and checks dev

Run both of these before calling any change done. Together they take about 10 seconds.

npm test

Syntax-checks every first-party JS file, then runs the lints that fail on UI chrome written in CJK characters and on emoji anywhere in the game.

npm run checks

Runs every scenario check in scripts/sim/checks/. Each one sets up an exact game situation (a marriage crisis, a tournament, a succession) and prints ok or FAIL. New files in that folder are picked up automatically. To run just one check: node scripts/sim/checks/family-marriage.js

Data export dev

Exports the game's declarative data (assets/data/*.js) to language-neutral JSON for the Unity/C# port of the sim. One JSON per source file, plus a manifest.json. It only reads the repo and writes to ascendant/Assets/Data/; it never touches assets/.

npm run export:data

Regenerates the JSON. Non-finite numbers (the Ascension stage's qiCap: Infinity) are preserved as {"__number__":"Infinity"}. Function-valued data (the random events' apply) cannot be JSON and is listed under manifest.logicToPort for hand-porting to C#.

npm run export:data:check

The drift check: exits 1 if the JSON is stale, missing or orphaned. Run it after changing any assets/data/*.js file.

Add --report to print the logic-to-port list: node scripts/export-sim-data.js --report. Full context is in the 3D port plan and ascendant/docs/.

QA sim bot bot

Bots play the real game logic headless at full speed and write a pacing, fun and health report. Open scripts/sim/out/report.md when it finishes (full detail is in report.json).

npm run sim:quick

Quick smoke run: the active and afk bots, 24 in-game hours, 1 seed. Takes about a second. Writes its report to scripts/sim/out/quick/.

npm run sim

Full suite: the active, casual and afk bots, each at 50, 100 and 200 hours, over 3 seeds.

npm run sim -- --profiles=casual --hours=100 --seeds=5

Custom run. Put the flags after --.

FlagWhat it does
--profiles=a,bWhich bots to run: active, casual, afk
--hours=50,100In-game hours to simulate. Each value is a separate fresh run.
--seeds=N / --seed=NHow many runs per combination / the first seed (default 1). The same seed always gives the same result.
--path=founder|memberWhether the bot founds its own sect or stays a sect member forever
--set="EXPR"Overrides a balance value without editing the file. You can repeat it. Example: --set="SECT_FOUNDING.minStage=15"
--dt=1Seconds per game tick (the real game caps it at 2)
--out=DIR / --quietWhere to write the report / hide the progress line

Exit codes: 0 means healthy, 1 means errors or broken invariants were found, 2 means the harness itself crashed. For a balance change, run the sim before and after it, and try values with --set before editing any data file.

Real-app smoke tests bot

node scripts/smoke/cdp.js scripts/smoke/scenarios/layout-modes.js

Launches the real Electron app with a throwaway profile, so your saves are never touched. It then drives the app through a scenario, fails on any console error, and saves screenshots to scripts/smoke/out/. The window opens on your second monitor, not the primary one, and without stealing focus, so a run never covers your work. Swap in any file from scripts/smoke/scenarios/, for example character, family, sect, mobile, nav-attention or ux-audit.

$env:CULTIVATOR_SMOKE_DISPLAY=2; node scripts/smoke/cdp.js scripts/smoke/scenarios/layout-modes.js

Pins the smoke window to a chosen display (1-based: 1 = the primary, 2 = your second monitor). Leave it off and the harness uses the first secondary display it finds.

Desktop builds build

npm run dist

Builds the Windows x64 portable app into dist/Cultivator Idle-win32-x64/.

npm run dist:mac

Builds the macOS app for x64 and arm64.

npm run build:web

Assembles www/ from renderer/ and assets/. This folder is the web bundle that both mobile shells load. Run it after any change to platform-storage.js or the main.js IPC.

npm run release

The all-in-one ship script. Runs npm test + npm run checks, builds the Windows portable app, builds + uploads the Android .aab, syncs the iOS web bundle, triggers the Codemagic TestFlight build, and creates a GitHub Release with the Windows zip attached. It knows what it can build locally and what it can't — a step with no credentials prints SKIPPED and the rest still runs. It never commits or pushes your code.

Partial runs: npm run release -- --only=win (steps: checks,win,android,ios,github), --skip-checks, --version=0.2.0, --notes="what changed".

VariableUnlocks
GITHUB_TOKENThe GitHub Release + Windows zip upload (PAT with the repo scope)
PLAY_SERVICE_ACCOUNT_JSONThe Google Play internal-track upload
CODEMAGIC_API_TOKEN + CODEMAGIC_APP_IDThe iOS TestFlight build on Codemagic's free macOS runners
$env:GITHUB_TOKEN="ghp_REPLACE"; $env:PLAY_SERVICE_ACCOUNT_JSON="$PWD\google-play-service-account.json"; npm run release
Full reference — steps, flags, versioning, credentials, gotchas: docs/systems/release.md.

Android android

npm run release:android

The main Android command. It runs npm test, then build:web and cap sync android, bumps the versionCode, builds a signed .aab with Gradle, and uploads it to Google Play. With no Android SDK installed it skips the Gradle build, and without a service-account key it skips the upload, printing a clear message either way. It never commits or pushes.

npm run cap:sync:android

Rebuilds www/ and copies it into the Android project.

npm run android:open

Syncs, then opens the project in Android Studio (use this for emulator or device runs).

npm run android:bundle

Only the Gradle build. Output: android/app/build/outputs/bundle/release/app-release.aab. This script is Windows-only; on macOS or Linux, run cd android && ./gradlew bundleRelease.

Environment variables for release:android:

VariableDefaultMeaning
PLAY_SERVICE_ACCOUNT_JSONunsetPath to the Play service-account key. If unset, the upload is skipped.
PLAY_TRACKinternalinternal, alpha (closed) or beta (open)
PLAY_RELEASE_STATUScompletedcompleted releases right away; draft uploads without releasing
PLAY_VERSION_CODEprevious + 1Overrides the automatic versionCode bump
PLAY_PACKAGEcom.cultivator.idleThe application id
$env:PLAY_SERVICE_ACCOUNT_JSON = "C:\keys\google-play-service-account.json"
npm run release:android
Before your first Android release:
  • Signing: copy android/keystore.properties.example to android/keystore.properties and point it at your upload keystore. Without it the .aab builds unsigned and Play rejects it. Never commit keystores or keys; they're already in .gitignore.
  • Java: Gradle needs JDK 17–24. The script finds one automatically. Don't point it at Android Studio's bundled JBR (Java 25), which fails with Unsupported class file major version 69.
  • Play Console: create the app, enable Play App Signing, fill in App content, add testers to the internal track, and create a service account with "Release to testing tracks". The first upload has to be manual.
Full details are in docs/systems/android-port.md.

iOS build

npm run cap:sync

Rebuilds www/ and syncs it into ios/.

npm run ios:open

Syncs, then opens the project in Xcode. This needs a Mac; on Windows, iOS builds run on Codemagic through npm run release.
